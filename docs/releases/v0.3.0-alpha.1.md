# Kelyro v0.3.0-alpha.1

`v0.3.0-alpha.1` is the I-04 Curriculum Compiler & Learning Packs prerelease.
It turns frozen, verified I-03 Source Bundles into deterministic learner-neutral
curricula and immutable portable packs while preserving I-02 student state.

## Added

- Versioned goal decomposition, professional outcomes, competency matrices,
  concept extraction/atomization, prerequisite expansion, vocabulary and
  knowledge graphs, visible hierarchy construction and a deterministic
  compiler pipeline.
- Multidimensional coverage and gap analysis, definition-before-use,
  zero-assumption, beginner simulation, expert review, production/toolchain/
  security coverage and current/experimental/legacy/historical guidance.
- Learning Pack v1 directory/ZIP format, strict loader, checksums, dependency
  resolution, immutable installation/activation, offline catalog inspection,
  change classification and backup-protected student-safe upgrades.
- Environment Pack v1 and phase-aware Doctor diagnostics with trusted probes,
  official guidance metadata and no pack-authored execution.
- Reproducibility build metadata, evidence reports, copyright-aware builds,
  curriculum/pack CLI commands and Curriculum/Pack TUI views.
- A deterministic preview-only Backend Go reference pack plus 10,000-concept
  scale and end-to-end pack lifecycle fixtures.

## Fixed

- Prerequisite hierarchy ordering now introduces hard prerequisites before
  dependants, even when alphabetical order would invert them.
- Pack activation creates the I-02 Curriculum Instance for the active goal,
  remains idempotent and blocks direct version transitions that bypass safe
  migration.
- The active Environment Pack now feeds real Doctor output.
- Verified prerequisite expansion no longer rejects valid evidence-backed
  roots.
- Directory pack validation canonicalizes both root and entries, so native
  macOS `/var` → `/private/var` resolution and other symlinked ancestors do not
  create false escape findings; actual symlink entries remain rejected.
- Cross-platform tests now use native configuration-directory semantics and do
  not assert POSIX permission bits on Windows.

## Security and privacy

- The compiler performs no live discovery, fetch or release lookup. It accepts
  only frozen I-03 bundle/claim identities and works with network access off.
- Pack loading rejects traversal, links, duplicate entries/keys, active or
  executable content, unsafe Markdown, oversized/decompression-hostile input,
  raw retained source bodies and unlicensed authored assets.
- Curriculum migration is planned and executed through application services;
  it never invents mastery and backs up state before an authorized upgrade.
- Packs cannot add executable Doctor probes, commands, installers, credentials,
  plugins or AI behavior.

## Verification

- Complete local `go test ./...`, `go vet ./...`, `go test -race ./...`,
  I-01–I-04 E2E and build/smoke gates.
- Hosted Ubuntu, macOS and Windows quality matrix, including full Linux race
  coverage: [CI run 35167579774](https://github.com/mishaaac/kelyro/actions/runs/35167579774).
- Manual production-binary dogfooding of compile, validation, coverage, gaps,
  audits, build info, pack validate/install/list/show/activate/upgrade,
  roadmap, Doctor and offline catalog behavior.
- Manual review of every reference-pack concept and its advanced, security and
  production modules; no critical I-04 bug remains known.

## Known limitations

- The Backend Go reference pack is a preview development fixture with
  `optional_for_fixture` evidence; it is not a production-complete curriculum.
- Lesson prose/runtime, practice and assessment execution, projects and AI Tutor
  behavior remain assigned to I-05 or later specifications.
- Pack signatures and publisher trust roots are not implemented. Checksums
  detect corruption but do not authenticate a publisher.
- The catalog consumes validated local/offline metadata; it does not download
  or install remote artifacts automatically.
- `kelyro update check` reports application releases but does not install them.

## Compatibility

- The application version advances from `0.2.0` to the `0.3.0` prerelease line
  because I-04 adds a new public product layer; pack versions remain independent.
- Forward-only migrations preserve existing I-01/I-02/I-03 workspaces and
  published migrations are unchanged.
