# Kelyro v0.2.0-alpha.2

`v0.2.0-alpha.2` is the I-03C Live Research Closure prerelease. It completes
the missing production path from a user research topic to public discovery,
durable Evidence and Claims, verification, and a Source Bundle while preserving
the I-01/I-02 offline behavior shipped by earlier prereleases.

## Added

- A production Brave Web Search adapter behind the existing provider-neutral
  `SearchProvider`, with bounded pagination, strict response validation, a
  fixed HTTPS endpoint, and conformance coverage.
- Provider configuration, Foundation Secrets integration, Doctor readiness,
  privacy gating, and durable per-run search/provider-call cost accounting.
- Synchronous consumption of the existing Research queue from
  `kelyro research topic`, with one versioned orchestrator and transactional
  terminal settlement of run, queue, audit, cost, and bundle identity.
- Complete production wiring for search results, candidate deduplication,
  Source registration, HTTP fetch, snapshots/cache, normalization,
  deterministic extraction, trust/freshness, multi-source verification,
  Source Bundle assembly, and provenance.
- Deterministic E2E coverage for query-to-bundle, privacy denial, partial
  source failure, retry/idempotency, offline reopening, provider conformance,
  and explicit live query smokes.

## Fixed

- Natural CLI topics now interoperate with conservative
  `evidence-extractor-v2` and `claim-extractor-v2` without treating search
  snippets or ambiguous prose as Evidence.
- Successfully normalized public Sources receive deterministic post-fetch
  classification independent of provider rank, title, and snippet.
- `multi-source-verification-v2` can preserve qualified official support as
  `verified_with_caveat` without silently converting `requires_verification`
  into accepted trust or inventing reviewed organization ownership.
- `live-bundle-claim-selection-v1` excludes insufficient/rejected Claims from
  a supported bundle while retaining those artifacts for audit.
- `live-source-fetch-v2` allocates the durable fetch/byte budget before
  concurrency, producing deterministic source selection without increasing
  network limits.
- A new Linux Secret Service collection can store its first Kelyro secret;
  true keychain backend failures remain diagnostic.
- The full live query-to-bundle smoke now uses the same v2 extractors as the
  production composition root.

## Security and privacy

- Live search and fetch remain deny-by-default through
  `privacy.allow_network`; selecting Brave never grants network permission.
- The API credential exists only in Foundation Secrets under
  `research.search.brave.api_key`; it is excluded from TOML, SQLite, logs,
  audit records, and release artifacts.
- Search results remain untrusted candidates. Only validated URLs whose
  fetched content passes snapshot, normalization, literal extraction, trust,
  freshness, and verification can support a bundle.
- Search/fetch limits, SSRF and redirect controls, response/decompression
  bounds, cancellation, cost reservations, and external-content retention
  remain enforced.

## Known limitations

- Brave is the only production SearchProvider in this prerelease. Users must
  explicitly select it, store a valid credential, and allow network access.
- Mutable public content can legitimately produce no Claim or bundle. Fresh
  workspaces without reviewed Registry ownership normally expose qualified
  official support as `ready_with_caveats` rather than full trust.
- No production Curriculum Compiler, Learning Pack generation, AI Research
  Reviewer/runtime, plugin platform, crawler, browser renderer, or background
  research daemon is included.
- `kelyro update check` reports releases but does not install them.
- `SHA256SUMS` detects corruption but is not a cryptographic publisher
  signature.
