# Student Core terminal experience

Step 26 turns the Foundation terminal shell into the first persistent learning
experience. Bubble Tea remains a presentation adapter: it requests application
read models and operations asynchronously and never opens SQLite, calculates
analytics, traverses prerequisite policy, or selects daily work.

## Screens and navigation

After learner setup, Home presents the active goal, curriculum completion,
reviews due, next planned concept, effective mastery requirement, current streak, and
study time for the local week. The primary destinations are:

- `Enter` or `t`: Today;
- `r`: Roadmap;
- `p`: Progress;
- `c`: current Concept detail;
- `v`: Reviews;
- `h`: History;
- `g`: Goal;
- `o`: Profile;
- `f`: refresh the dashboard.

Onboarding remains resumable and automatically opens while learner setup is
incomplete. When setup completes, the TUI loads a fresh dashboard before the
learner returns Home. Doctor, Config, and the standalone non-punitive Streak
view remain available as secondary Foundation utilities.

The requirement comes from `MasteryPolicyService`, so a workspace override is
shown instead of the goal default when threshold precedence selects it. Today
renders the ordered `daily-plan-v1` selection and its explanations; it
does not construct or assess exercises. Progress separates curriculum
completion from average mastery over known concepts and explicitly renders an
absent average as `unknown`. Reviews and History use their existing application
services. Goal and Profile remain read-only views in the TUI.

## Roadmap and concept state

The TUI renders `ProgressDashboard.Roadmap`, whose hierarchy and educational
status are already resolved by application. Text labels carry all meaning:
`mastered`, `current`, `available`, `locked`, and `review due`. Color is only
decoration. Locked concepts show the supplied `Why` explanation, and Concept
detail repeats the reason without recomputing it.

Mastery is a pointer in the roadmap projection. No observation is shown as
`unknown`; a known evidence-derived score of zero remains `0%`. This avoids
conflating absence of evidence with measured low mastery.

## Refresh, errors, and session state

Initialization and explicit refresh call the workspace-scoped dashboard
application boundary. Refresh replaces the complete read model, including a
daily plan regenerated by its source fingerprint when necessary. Reviews,
History, Profile, and Streak keep their own focused loading and retry states.
Failures remain local to the screen and do not make the terminal unusable.

Student Core destinations are valid resumable session views. Only meaningful
navigation is checkpointed; terminal width, loading flags, cached projections,
text buffers, viewport height, and scroll position remain ephemeral. Every view
wraps or truncates content to the available display width. When a read-only view
is taller than the terminal, an internal height-bounded viewport keeps the first
page visible and reports the visible line range; arrow keys scroll one line,
`j`/`k` provide the same navigation outside Home, and Page Up/Page Down,
Ctrl+U/Ctrl+D, Home, and End move by page or boundary. Config and onboarding
retain those keys for selection and input. Shortcuts wrap onto additional lines,
and the UI does not depend on Unicode symbols or color for semantics.

## Boundaries

Step 26 adds no public Student Core CLI commands, Markdown progress export,
schema migration, Exercise Engine, Research Engine, Curriculum Compiler, AI
provider, plugin, generated learning content, or automatic network activity.
